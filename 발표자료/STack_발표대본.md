[S04]

방금 보신 것처럼 과목에 들어가서 자료 하나를 내려받고, 다운로드 폴더와 PDF 뷰어, 외부 AI 앱을 거쳐 다시 이클래스로 돌아와 과제 마감까지 확인하는 데 클릭 여덟 번, 화면과 앱을 네 번이나 옮겨 다녀야 합니다. 한 과목만 해도 이렇습니다. 마감일, 강의자료, 녹음, 그 녹음을 다시 들으며 하는 필기까지 전부 따로 놀고 있기 때문입니다.

[S05]

방금 영상에서도 보셨듯이, AI로 복습하려고 PDF를 내려받아 외부 서비스에 일일이 다시 올리죠. 그런데 기존 대안들은 결국 둘 중 하나를 포기하게 만듭니다. 먼저, 유니브 AI 같은 업로드형은 파일이 앱마다 흩어지다 보니 나중에 볼 때 '이 PDF가 몇 주차 과제랑 이어지는 거지?' 하고 매번 다시 맞춰봐야 합니다. 과목이나 마감 일정은 모르니까요. 반대로 GPAI 같은 연동형은 학교 아이디와 비밀번호를 외부 서버에 맡겨 두고, 그 서버가 대신 로그인해서 자료를 가져오는 방식인데요. 실제로 이번 달에 충북대와 서경대가 외부 서비스에 학교 계정을 입력하지 말라고 공지했고, 이클래스 운영사 유비온도 IP 차단을 안내했습니다. 잘 쓰던 도구가 하루아침에 막히는 셈입니다. 결국 업로드형 AI는 학습 흐름이 끊기고, 연동형 AI는 계정을 맡겨야 해서 학교가 막고 있습니다. 저희는 바로 그 사이를 풀고 싶었습니다.

[S06]

저희는 이 두 가지 문제를 각각 원칙 하나로 풀었습니다. 첫째, '한 화면 흐름'입니다. 예전처럼 복잡한 하위 메뉴를 뒤질 필요 없이, 에이전트한테 말만 걸면 원하는 강의나 과제, 자료 페이지를 바로 찾아 열어 줍니다. 마감 확인부터 자료 보기, 요약, 강의 녹음까지 한 화면에서 쭉 이어집니다. 둘째, '과목 안에 묶기'입니다. 자료를 외부 앱으로 빼돌리지 않고 해당 과목과 주차 방 안에만 차곡차곡 모아둬서, 학교 서버가 불안정할 때도 내 복습은 멈추지 않습니다. 학교 계정은 로그인할 때 한 번만 확인하고 비밀번호는 저장하지 않습니다. 마지막 셋째는 '자동 정리'입니다. PDF를 올리면 페이지마다 해설이 붙은 요약으로 정리됩니다. 그리고 수업은 녹음만 하면 필기는 STack이 대신합니다. 녹음하는 동안 바로 받아 적고, 끝나면 시각별 전사와 요약으로 같은 과목 학습실에 쌓입니다.

[S07]

말보다 화면으로 직접 보시는 게 빠를 텐데요. STack을 처음 켜는 학생 입장에서, 에이전트로 원하는 기능을 바로 불러내 강의 녹음으로 필기까지 끝내는 과정을 1분 47초 동안 보여드리겠습니다. 할 일이 많을 땐 플랜 모드에 한 번에 맡기는 모습도 함께 보시겠습니다.

[S09]

말로만 원칙을 세운 건 아니고, 실제 코드 구조도 이 세 가지에 맞춰 설계했습니다. 먼저 첫 번째, 한 화면 흐름과 에이전트 기능은 프론트엔드의 에이전트 실행 모듈과 백엔드 API 서버에 구현했습니다. 과목 학습실에 한 번 들어가면 마감, 자료, 요약, 녹음이 전부 같은 상태를 공유하도록 짰고요. 두 번째, 과목 안에 묶기는 파일 저장 모듈과 서버의 학습실 서비스가 담당합니다. 올린 파일은 수강 과목에, 녹음은 사용자와 과목에 딱 묶어둬서 다른 과목이나 다른 사람이 볼 수 없고, 학교 서버가 흔들려도 학습 데이터는 STack 서버에 안전하게 남습니다. 세 번째, 자동 정리는 PDF의 경우 서버의 요약 파이프라인에서, 수업 녹음은 올리자마자 서버가 전사와 요약을 만들어 녹음 학습 화면에 필기처럼 보여 줍니다. 처음엔 저희도 기능별로 페이지를 따로 나눌까 고민했습니다. 하지만 페이지가 갈라지면 결국 기존 이클래스와 다를 게 없어진다고 판단해서, 에이전트와 한 화면 구조를 묶는 쪽을 택했습니다.

[S10]

말 한마디에 수강 과목과 할 일 목록을 붙여 보내면, AI는 이동, 고르기, 계획처럼 정해 둔 일곱 가지 동작 중 하나만 고릅니다. 서버가 그 답이 내 과목, 내 할 일인지 다시 검증하고, 정해진 화면 경로로만 이동시킵니다.

[S11]

확장은 두 가지 트랙으로 갑니다. 트랙 A는 학교가 이미 쓰고 있는 이클래스나 LMS에 STack만 얹는 애드온 방식이고, 트랙 B는 저희가 개발 중인 이클래스와 STack을 묶어 LMS 전체를 교체하는 방식입니다. 둘 다 학교와 연간 계약하는 B2B 모델이고, 가격은 학생 한 명당 연 3만 원, 5만 원으로 책정했습니다. 서울대가 생성형 AI 서비스에 1인당 연 8만 원 넘게 책정한 것과 비교하면 부담을 낮춘 수준입니다. 트랙 B 기준으로 보면 전국 4년제와 전문대 재학생 181만 명, 약 909억 원이 전체 시장이고, 4년제만 따져도 약 711억 원 규모입니다. 첫해에는 서울과기대에 애드온으로 도입해 약 3억 3천만 원, 둘째 해에는 국립대로 넓혀 약 27억 원, 셋째 해에는 사립대까지 총 열다섯 개 대학, 약 48억 원 매출이 목표입니다. 애드온으로 먼저 진입하고, LMS 교체 시기가 온 학교는 묶음으로 가져가겠습니다.
