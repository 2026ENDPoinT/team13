# ADR-0024 강의실 질의응답과 열린게시판은 과목마다 하나인 게시판의 게시글로 둔다

## 상태
채택 (2026-11-11)

## 맥락
강의실 질의응답(화면 49~51, EP-0059~0074)과 열린게시판(화면 53, 54, EP-0016~0022)을 구현한다. 공지는 이미 과목마다 하나인 공지 게시판의 `posts` 행이다([ADR-0013](0013-course-notice-storage.md)). 원본 열린게시판은 게시판 그룹 번호(`ARTL_GRP_ID`)로 과목에 여러 개를 둘 수 있지만, 게시판을 만들고 이름을 바꾸는 담당자 화면은 캡처에 없다. 질의응답은 원본에서 익명 선택(`OPEN_YN`) 하나만 보이지만, 서버 요구(EP-0059, EP-0074, COMM-09)는 "비공개 질문은 작성자와 교수만 본문을 본다"와 "익명 작성자 이름은 교수 외에게 내보내지 않는다"를 따로 적는다. V1의 `posts`에는 `is_anonymous`와 `is_secret`이 둘 다 있다. 질문 수정·삭제 조건(답글 전)과 답글 작성이 동시에 일어날 수 있다.

## 결정
1. 질의응답(`K002`)과 열린게시판(`K004`)은 과목마다 하나다. 첫 글을 쓸 때 공지와 같은 방식으로 만든다. V23이 생성 열 `course_board_key`와 `UNIQUE (course_id, course_board_key)`를 더한다. 게시판 생성은 공지와 함께 `CourseBoards` 하나가 맡는다.
2. 질문은 `post_kind = 'QUESTION'`, 답글은 `parent_post_id`가 질문인 `ANSWER` 행, 열린게시판 글은 `ARTICLE` 행이다. 댓글은 열린게시판 글에만 달고 `comments`에 둔다. 답글의 댓글(화면 51 미확인)은 만들지 않는다.
3. 익명과 비공개는 다른 축이다. 익명(`is_anonymous`)은 다른 학생에게 작성자 이름을 숨기고 담당자에게는 보인다. 비공개(`is_secret`)는 질문 자체를 작성자와 담당자만 보게 한다. 비공개 질문은 다른 학생에게 목록, 상태별 건수, 검색, 상세, 답글, 읽음, 추천, 첨부 어디에도 없다. 원본처럼 잠금 카드로 제목을 보이지 않는다. 작성자 ID는 익명이어도 저장하고 응답에는 어떤 경우에도 넣지 않는다(SC-07).
4. 질문은 수강생이 쓰고, 답글은 질문을 볼 수 있는 구성원 누구나 단다(EP-0064). 질문은 답글이 없을 때만 작성자가 고치고 지운다. 답글 수(`answer_count`)를 답글 작성·삭제와 같은 transaction에서 바꾸고, 질문 수정·삭제는 `answer_count = 0`을 조건으로 하는 조건부 UPDATE다. 답글 작성은 질문 행을 먼저 잠그므로 둘이 겹치면 한쪽이 먼저 끝나고 다른 쪽은 그 결과를 본다.
5. 담당자는 그 과목의 어떤 글, 답글, 댓글이든 지울 수 있다. 남의 것을 지우면 감사 기록의 연산 이름이 `*.moderate`다. 수정은 작성자만 한다.
6. 해결 상태와 FAQ는 목표 상태를 받는 PUT이다(EP-0072). 해결 상태는 질문 작성자와 담당자, FAQ는 담당자만 바꾼다. 내용 수정이 아니므로 `version`을 올리지 않는다.
7. 추천은 `post_likes`의 (글, 사용자) 유일 행이고 취소는 행 삭제다. 읽음은 공지와 같은 `post_read_receipts`를 명시적 POST로 남긴다. 추천·읽음·답글·댓글 명령은 글 행을 먼저 잠근 뒤 딸린 행을 바꾸고 집계 열(`like_count`, `view_count`, `answer_count`, `comment_count`)은 행을 실제로 만들거나 지운 때만 바꾼다.
8. 질의응답 목록은 원본처럼 쪽 번호를 쓰고, 첫 쪽 응답의 `snapshot`(그때 가장 큰 글 ID)을 다음 쪽 요청에 보내면 새 질문 때문에 쪽이 밀리지 않는다. 열린게시판, 답글, 댓글은 원본이 이어 붙이는 목록이라 ID cursor를 쓴다. 정렬은 모두 ID 순서 하나라 client가 고르지 않는다.
9. 첨부는 용도 `post_attachment`(그 과목의 구성원)로 올리고 글을 저장하는 transaction에서 확정한다. 파일 권한은 `PostAttachmentAccess`가 글의 권한으로 판정한다. 비공개 질문과 그 답글의 파일은 질문 작성자와 담당자만 읽고, 지운 글의 파일은 아무도 읽지 못한다. `Attachments`에 첨부 교체·해제 계약이 없어서 수정은 텍스트만 바꾸고, 삭제는 글만 소프트 삭제한다.
10. 만들기 명령은 공용 멱등 원장([ADR-0012](0012-idempotency-ledger-and-audit.md))을 쓰고 header는 선택이다. 공지가 쓰는 `posts.client_request_id`는 새 글에 쓰지 않는다.

## 결과와 트레이드오프
- 공지, 질의응답, 열린게시판이 같은 게시판·게시글·읽음 테이블과 게시판 생성 코드를 쓴다. 게시판 종류마다 테이블을 나누면 읽음, 첨부, 감사 처리가 셋으로 갈린다.
- 과목에 열린게시판을 여러 개 둘 수 없다. 담당자 게시판 관리를 만들 때 V23의 생성 열 조건에서 `K004`를 빼고 경로에 게시판 ID를 넣는다. 원본의 `ARTL_GRP_ID`는 `boards.legacy_artl_grp_id`로 옮길 수 있다.
- 비공개 질문을 잠금 카드로도 보이지 않으므로 다른 학생의 전체 건수가 원본보다 작을 수 있다. 건수로도 비공개 질문의 존재를 알리지 않는 쪽을 택했다.
- 답글이 달린 뒤에는 학생이 질문을 고칠 수 없어서 오타도 고치지 못한다. 답글이 질문의 원래 내용을 전제로 쓰였기 때문에 담당자의 답이 엉뚱해 보이지 않게 하는 쪽을 택했다.
- 쪽 번호 목록의 `snapshot`은 ID 할당 순서와 commit 순서가 같다고 본다. 거의 같은 순간에 작은 ID의 transaction이 늦게 commit하면 그 글 하나가 이미 받은 쪽 뒤에 끼어들 수 있다.
- 첨부를 고치려면 글을 지우고 다시 써야 한다. `files.api.Attachments`에 교체·해제가 생기면 수정 요청에 첨부 목록을 받는다.
